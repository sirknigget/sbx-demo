# Planning

Understand the request and inspect relevant project guidance and existing behavior before choosing
an approach. Resolve material gaps with the user; do not ask for facts available in files or tools.
Choose the smallest solution that meets the request, reuse existing conventions, and define
observable completion and proportionate verification.

- When planning is only part of implementation, keep the plan internal and continue working.
- When asked to show a plan before coding, give a concise sequence of steps and verification; wait
  for approval before implementing if confirmation is requested.
- When asked for a detailed plan or plan file, include scope, decisions, affected components,
  execution order, and acceptance checks. Create a file only if requested.

Keep each step actionable. Do not present speculative work as required or silently decide material
product tradeoffs on the user's behalf.
